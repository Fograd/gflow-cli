# Saved TTS voice adapters

Scope: native saved-TTS voice list/detail/delete, followed by creation only where a measured outgoing contract exists. System preset assignment and saved TTS generation are distinct. No cloning, paid speech submission, solver task, guessed RPC or placeholder fields.

## Scenarios

- A system preset must never be treated as a deletable saved identity.
- Empty or ambiguous saved inventory is not proof of account-wide absence.
- Detail may refresh a playback URL only through an observed owned operation; signed URLs stay out of logs.
- Delete verifies selected-project ownership immediately before its one mutation; an unknown acknowledgement never causes replay.
- Active profile lease contention or missing login prevents access; no cookie cloning or forced browser termination.
- Create validates preset, dialogue/performance lengths and display name before browser; merely capturing a blocked wire is not accepted speech proof.
- CLI/MCP confirmation is an exact boolean at the registered boundary; SDK/REST preserve typed mutation uncertainty.
- Cancellation and page/client cleanup must retain acknowledged identity without changing failure into success.
- Windows/macOS/Linux paths are irrelevant to saved identity commands; no local-file voice cloning interface is introduced.
